# 方法论前置声明（阶段0）

> 本文档是 notebooks/01–05 的方法论基准。四个陷阱声明 + 两条补充边界声明 + 因果推断四问，
> 后续每个 notebook 的分析口径与措辞都必须与本文档一致，不得偏离。

## 0. 数据与问题定位

- 数据来源：UCI Machine Learning Repository **Bank Marketing**（`data/raw/bank-additional-full.csv`），41,188 行 × 21 列，每行是**一次外呼活动记录**。
- 目标变量 `y`：是否办理定期存款（正类 11.27%，负类 88.73%）——类别不平衡，模型评估不得只看 Accuracy。
- 处理变量 `contact`：联系渠道，`cellular`（手机，26,144 条，63.5%）vs `telephone`（座机，15,044 条，36.5%）——**非随机分配**。
- 本项目回答的核心问题："把外呼渠道统一改为手机联系，是否真的提升了转化率，还是客群差异造成的假象？"

---

## 1. 四个陷阱声明

### 声明一：duration 数据泄漏

- `duration`（本次通话时长）是**结果而非原因**：只有客户表现出兴趣，销售才会持续通话，通话时长本身就是转化信号的一部分。
- 任何"外呼前决策"用途（预测模型、评分模型、匹配混杂变量）**一律禁用 duration**。
- 仅允许在事后 EDA 中使用，且必须显式标注"**解释用途，非预测/决策用途**"。
- 执行口径：notebooks/02、03 的模型特征集、04 的倾向得分混杂变量集均剔除 duration；如有 EDA 引用，在引用处显式标注。

### 声明二：选择偏差（本项目引入 PSM 的根本原因）

- `contact`（渠道）和 `campaign`（次数）都**不是随机分配**的：销售人员根据客户特征和现场判断决定"用什么渠道打、打多少次"。
- 朴素组间比较（cellular vs telephone 的平均转化率之差）**无法区分**"渠道本身的差异"与"被分配到不同渠道的客群本身差异"。
- 这正是 PSM 的适用场景：用可观测混杂变量重建"两组客户在可观测特征上可比"的条件，把朴素比较中的选择偏差部分剥离出来。

### 声明三：PSM 适用边界

**能用 PSM 的前提（必须全部满足才能做）：**

1. 处理变量**非随机分配**，且分配决策发生在"协变量可观测"的时点（渠道分配时，人口统计特征、历史接触痕迹都已存在）；
2. 影响处理分配的**可观测混杂变量基本齐全**（本项目：人口统计 + 历史行为痕迹）；
3. 不存在**反向因果 / confounding by indication**——即处理本身不是"对结果预期的反应"；
4. 共同支撑域检查通过、匹配后平衡性检验（SMD）通过。

**本项目判定：**

| 变量 | 是否做 PSM | 理由 |
|---|---|---|
| `contact`（渠道） | ✅ 做 | 非随机分配、可观测混杂基本齐全、无反向因果（渠道分配先于通话结果） |
| `campaign`（次数） | ❌ 不做 | 反向因果 / confounding by indication，见声明四 |
| `duration` | ❌ 禁用 | 数据泄漏，见声明一 |

**措辞规范（强制）：** PSM 调整后的估计**不允许称为"因果效应"**，必须使用"**经可观测因素调整后的效应估计**"这类措辞。PSM 只能平衡可观测混杂，未观测混杂的影响必须用敏感性/局限声明兜底。

### 声明四：为什么 campaign 不做 PSM

- `campaign`（本次活动的联系次数）存在**反向因果（confounding by indication）**：打更多电话本身就是"销售判断这个客户有希望"的**结果**——销售对高意向客户会主动多打。
- 而销售的**主观判断不可观测**。对 campaign 做 PSM，等于假设"打 n 次电话的决策完全由可观测特征决定"，违反条件可交换性假设；无论 SMD 匹配得多平衡，这一核心混杂都无法被平衡。
- 因此对 campaign **只做描述性边际分析**（notebook 05：外呼次数与转化率的描述性关系），不做任何因果声称。
- 这是**主动的方法论取舍，不是遗漏**——识别"什么变量连 PSM 都不该用"，本身就是本项目的能力目标之一。

## 2. 补充边界声明

### 2.1 无客户唯一 ID

- 数据集**没有客户唯一标识**，每行是一次外呼活动记录，无法跨活动追踪同一客户。
- 生命周期分层是"用当前活动可观测的历史痕迹字段（`previous`/`pdays`/`poutcome`）重建的**近似状态**"，不是真正的纵向留存追踪。
- 执行口径：notebook 01 及所有引用生命周期分层的 notebook 必须显式声明这一边界。

### 2.2 类别不平衡

- 正类（办理定存）约 11.27%。
- 模型评估（notebook 03）不得只看 Accuracy（全预测"否"也能拿到 88.7% 的 Accuracy）；使用 AUC、Precision-Recall、Gains Chart 等对不平衡不敏感的指标。

### 2.3 pdays 哨兵值的口径

- `pdays=999` 的官方含义是"从未联系过"，但实际数据中存在 `pdays=999` 且 `previous>0`（即曾经联系过、但时间未记录）的记录——999 并不严格等价于"从未接触"。
- 执行口径：旅程定义一律用 `previous>0` 判定"回归客"，不单独用 `pdays!=999`。

### 2.4 生命周期分层的"计划 vs 数据现实"修正记录（01 执行时主动调整，非漂移）

**原计划**（阶段规划时定下的 5 类）：新客、曾成功、近期失败(≤30天)、历史失败重新激活(>30天)、边缘情况兜底类 Unknown_History（`poutcome=nonexistent` 但 `previous>0`）。

**执行中发现的数据现实（notebook 01 实际计算）：**

1. **`pdays∈(27, 999)` 的记录数为 0**：非 999 的 `pdays` 全部落在 0–27 天。原计划"近期失败(≤30天) / 历史失败重新激活(>30天)"的天数二分没有数据支撑——">30天且天数可考"的失败客户在 41,188 条记录中一条都不存在；
2. `pdays=999` 并不等价于"从未联系"（4,110 条曾联系记录的 `pdays` 同为 999，见 §2.3）——"历史失败"类的天数信息基本不可考；
3. **边缘情况核实**：`poutcome=nonexistent 且 previous>0` 的记录数为 0——数据中 `previous` 与 `poutcome` 完全互斥（`previous==0 ⟺ nonexistent` 35,563 条；`previous>0 ⟺ failure/success` 5,625 条），不存在需要兜底的冲突组合，Unknown_History 类不成立。

**修正结果（当前生效口径，与 notebook 01 一致）：**

- "近期"边界以数据实际窗口为准定为 **27 天**（非 999 的 `pdays` 上限），替代原计划的 30 天；
- "历史失败"类改用**可靠字段 `previous` 的次数**细分为"轻触达(=1次) / 重触达(≥2次)"，替代原计划按天数划分的"重新激活"类；
- 兜底类 Unknown_History 因数据中不存在该组合而取消；5 类仍互斥且覆盖全体（notebook 01 有 assert 校验 + 显式边缘情况打印）。

**性质声明**：修正动机全部来自上面三点数据事实，是"计划遇到真实数据后主动修正"的决策记录，不是实现过程中的无意识漂移。后续 notebook（02/03/04/05）一律使用修正后的口径。

### 2.5 04 PSM 的作用域决策：分层分析，主分析限定 first_time（02 执行后定案）

**决策**：04 不做全量 pooled PSM，采用**分层（stratified）设计**——主分析在 **first_time（新客）** 上做，returning（回归客）单独做范围受限的鲁棒性补充，且以匹配质量为门（匹配后样本过少或 SMD 不达标则**不下效应结论**，仅报告朴素差异并声明局限）。

**依据（notebook 02 的实际数字）：**

1. 渠道效应集中在 first_time：该组 contact Cramér's V=0.1219（p<1e-117），cellular 11.7% vs telephone 4.7%（差距 7.0pp）；returning 组 V=0.0108（p=0.42，不显著），cellular 26.8% vs telephone 24.8%（差距 2.0pp）。
2. returning 对照（telephone）仅 **403 条**，vs cellular 5,222 条（13:1 失衡）——caliper 匹配会丢弃绝大部分处理组，匹配质量无法保证。
3. 历史痕迹变量（poutcome/pdays/previous）在 first_time 组内为常数、在 returning 组内是强混杂——一个 pooled 倾向得分模型无法同时处理好这两个结构（旅程阶段与渠道效应混杂）。
4. pooled ATT 实际上被 first_time 主导（cellular 处理组中 first_time 占 20,922/26,144 ≈ 80%），分层后反而更精确地回答业务问题："**改渠道对哪类客群有效**"（新客是主战场，占记录 86.3%）。

full pooled PSM 明确不做，理由记入本决策，防止未来实现时"顺手"合并。

### 2.6 时间代理变量（宏观指标）的共线处理决策（02 执行后定案）

**背景**：`euribor3m`、`emp.var.rate`、`nr.employed`、`cons.price.idx`、`cons.conf.idx` 五个宏观指标都是**采集时间的代理**（月/季度级更新）；`month` 是直接的时间戳。

**实测共线性（VIF，>10 视为严重）：**

| 变量 | VIF | 判定 |
|---|---|---|
| `euribor3m` | **63.9** | 严重 |
| `emp.var.rate` | **32.9** | 严重 |
| `nr.employed` | **30.7** | 严重 |
| `cons.price.idx` | 6.3 | 中等 |
| `cons.conf.idx` | 2.6 | 尚可 |

（三巨头两两 Pearson 相关 0.91~0.97；上述为相关矩阵对角 VIF。）

**关键实证**：first_time 组渠道份额随月份剧烈变化（jun 10.5% → aug 95.9% 的 cellular 占比），而 `euribor3m` 在这两个月的分布几乎相同（中位数 4.96 vs 4.97）——**连续宏观代理区分不了月份，`month` 才能**。时间确实是渠道分配的混杂因素（影响 T 和 Y），不能剔除时间，但只需一个能区分月份的代表。

**决策（03 与 04 统一执行）**：

- 03 评分模型与 04 倾向得分模型的**时间代表只用 `month`（类别型）**；
- 五个宏观连续变量**全部不进模型**（03 与 04 均如此）；
- 理由：VIF 63.9/32.9/30.7 的共线组进入逻辑回归属教科书式多重共线性；`cons.price.idx`/`cons.conf.idx` 虽 VIF 可接受，但同为时间代理、信息已被 month 吸收；只用 month 可解释性最好。
- 可替换实现思路（敏感性检验用）：用 `euribor3m` 与 `month` 互换做对照（euribor3m 是连续精细时间代理，但如上实证无法区分 jun/aug 的渠道突变）。

## 3. 因果推断四问（每个 PSM 相关 notebook 必须显式回答）

1. **这个变量能不能做 PSM**（有没有反向因果 / 不可观测的核心混杂）；
2. **混杂变量选够了吗**（选择依据）；
3. **匹配后平衡了吗**（SMD 检验）；
4. **效应量多大、边界在哪**（ATT + 未观测混杂局限声明）。
