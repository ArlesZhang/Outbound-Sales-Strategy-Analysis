# Interview Preparation（正式版，Day6 定稿）

> **一句话定位**：这个项目的面试价值不是"我会 PSM"，而是"我在没有 AB 测试的真实业务困境里，知道怎么用观察数据逼近因果，并且诚实说出逼近不到的边界"。下面的五问话术全部由 04 实跑数字支撑，数字与 README 定稿逐字一致（README §3.4 的反直觉结论引用块与本文件 Q3 的核心句为同一文本）。

## 五问总览

1. 项目背景与业务价值 → 为什么做这个、货拉拉困境怎么来的
2. 数据分析方法选择 → 为什么是"分层+评分+PSM"这套组合、哪些方法明确不用
3. 为什么使用 PSM → 四件套 + 反直觉结论（调整后效应反而更高）
4. 方法局限性 → 未观测混杂、共同支撑域、returning 质量门
5. 实际工作中用得上吗 → 迁移回货拉拉的五个可复用经验 + 有客户 ID 会怎么重做

## Q1 项目背景与业务价值

**标准回答（约 90 秒）**：我在货拉拉三轮销售质检工作里反复遇到一类问题——**规则/话术调整上线后效果看起来变好了，但这是调整本身的功劳，还是客群/时段自然变化造成的假象？**这类调整几乎从不走 AB 测试，只有历史观察数据。做这个作品集的三个项目就是为了把这套能力补齐：项目一练描述性分析（发生了什么），项目二（Cookie Cats，有随机实验）练因果推断的标准答案，项目三（本项目，UCI Bank Marketing）练它的成对困境——**没有实验时的因果推断**。我在 UCI 数据上复刻了货拉拉困境：渠道（`contact`）和拨打次数（`campaign`）都不是随机分配的，由销售现场判断决定，朴素比较混着客群构成差异。回答的业务问题是：**把外呼渠道统一改为手机联系，是否真的因果性提升了转化率？**

**核心数字**：经可观测因素调整后的效应估计 = **+8.1 个百分点**（95% CI [+7.1, +9.2]，新客、两种独立匹配规格互相印证），朴素全量比较为 +9.51pp、限定新客后 +7.04pp——**9.51 → 7.04 → 8.13 的每一步变化都对应一个可解释的偏差来源**，这就是"把相关性逼近因果性"的过程。

### 追问预案：为什么不直接看朴素比较结果？（"你绕这么大圈干什么"）

朴素比较 9.51pp 混着两类偏差：约 2.5pp 是**旅程阶段混杂**（回归客混入拉高差异，9.51−7.04）；新客内部的 7.04→8.13 说明**客群构成的作用方向是反的**（见 Q3）。不匹配你根本不知道 9.51 里有多少是客群差异——这正是选择偏差的量化意义。

### 追问预案：为什么不做 AB 测试？

真实业务里很多调整没法走 AB（合规、资源、策略统一性）；AB 也有能力边界（渠道渗透率随月份剧烈变化时，实验窗口内可能根本没有可比的对照组月份）。本项目就是在"没有 AB"的前提下交出最好的答案——**并且明确交代这份答案覆盖不了哪些客群**（见 Q3 的 29.9% 预案）。

## Q2 数据分析方法选择

**标准回答**：六个阶段一条链——方法论声明 → 数据质量+用户旅程+生命周期分层 → 驱动因素分析 → 客户分层评分 → PSM 策略验证（核心）→ 节奏描述性分析。三个方法论取舍提前锁死：

1. **duration 数据泄漏**：通话时长是结果不是原因，任何"外呼前决策"模型一律禁用（01-05 全程 assert 自检）；
2. **campaign 反向因果**：打更多电话是"销售判断有希望"的结果，核心混杂不可观测 → 对 campaign 不做 PSM、只做描述性边际分析（05），04 用 assert 把它挡在倾向得分模型外；
3. **宏观共线**：`euribor3m`/`emp.var.rate`/`nr.employed` VIF 63.9/32.9/30.7（五个宏观变量互算；含 month 时更高），五个宏观指标全是采集时间的代理，统一剔除，时间代理只用 `month`（00 §2.6，03/04 同一纪律）。

**分层先于一切**：02 发现两个旅程阶段的驱动因素前三名**完全不重叠**（新客=市场时机三件套 `nr.employed`0.2497/`month`0.2446/`euribor3m`0.2188；回归客=历史三件套 `pdays_bucket`0.5123/`poutcome`0.4939/`nr.employed`0.4898）——旅程分裂决定了后续所有分析都要按 first_time/returning 分组进行，**混合估计会把策略效应洗淡**。

### 追问预案：为什么只用 LogisticRegression + NearestNeighbors 这套基础工具，不用 EconML/CausalML？

两个理由：(1) 本项目目标是把 **PSM 这一套方法做扎实、把边界讲清楚**，而不是展示工具箱广度——RDD/IV/合成控制法在多数货拉拉场景没有天然断点/工具变量，学了是噪音；(2) 对 PSM 每一步（倾向得分 → 共同支撑域 → 匹配 → SMD → ATT）我都能手写解释每一行的含义，这在业务会议上才是可信度来源。

### 追问预案：为什么用卡方检验 + Cramér's V 而非回归系数？

驱动因素阶段的目标是"哪些特征和转化相关、分旅程阶段是否不同"，Cramér's V 是无量纲关联强度、可直接跨变量比较（0.25 vs 0.51 的差距一目了然、不依赖量纲）；回归系数留到 03 的评分模型里用（那里需要系数做预测）。

## Q3 为什么使用 PSM（核心话术）

**标准回答（30 秒版）**：渠道非随机分配，朴素比较无法区分"渠道效果"和"客群构成差异"。PSM 做的事：用外呼前已知信息（人口统计 7 项 + 唯一时间代理 month，OneHot 后 41 维，倾向得分模型 AUC 0.8825）估计每个新客被分到手机渠道的概率，然后为每个手机组客户找一个**倾向得分相近的座机组客户**（caliper 0.3819 = 0.2×logit SD，最近邻，不放回），6,259 对 / 20,922 = **29.9% 匹配成功率**。最后在匹配样本上比转化率——**这就是"经可观测因素调整后的效应估计"**，我说它的时候永远不加"因果效应"三个字。

**四件套（缺一不可，倒背如流）**：混杂变量选择依据（为什么要这 7 项+month）→ 共同支撑域检查 → SMD 平衡性检验（49 个特征水平中 46 个匹配后 <0.1；`age` 0.0313→0.0291、`default_no` 0.2474→0.0061）→ ATT 估计（方案A +8.13pp [7.1, 9.2]；方案B +7.84pp [6.8, 8.9]，两规格互相印证）。

### 反直觉结论（先背这一句——与 README §3.4 同一文本）

> **匹配把"座机几乎没在用的月份（aug/jul/apr）"里那批手机组客户剔出了样本——被剥离的 14,663 人（占手机组 70.1%，派生：20,922−6,259）中约 79.5% 来自这三个月——而这批客户本身转化率偏低（10.9%，低于全体新客手机组的 11.7%），匹配后的样本手机组转化率被抬到 13.8%，所以调整后效应（8.1pp）高于朴素新客比较（7.0pp）。这不是 PSM 出错了，而是"ATT 只代表能找到可比座机组的那部分客群、不能外推到全体新客"这条局限的具体体现。**

### 预判追问 ①："那这个 PSM 结果是不是没意义了，因为它不能代表全体新客？"

**不是没意义，是适用范围更窄、但更可信**——分三点：

1. **它精确回答了它该回答的问题**："在两种渠道都真实可比的那部分新客群体里，渠道效应有多大"。这个群体的规模就是匹配成功的 **6,259 对 = 新客手机组的 29.9%**——不是零星样本，在该活动的新客样本里是一批有实际业务体量的客群（推广到其他活动时需重新评估可比性），在这个群体上给出 +8.1pp（95%CI [+7.1, +9.2]）的经可观测因素调整后的效应估计；
2. **对估计不了的部分，报告如实说"估计不了"，而不是假装能算**：aug/jul/apr 座机渗透率 84.8%~95.9%（座机仅 149/236/1,053 人 vs 手机 1,725/5,483/5,893 人），数据本身不含这些月份内部的渠道对照——匹配全部弃掉这些手机组（匹配成功率 29.9% 的来源）。你想给全体新客一个统一数字，那就只能回到朴素比较 9.5pp——而它恰恰混杂了选择偏差；两害相权，诚实声明边界比给一个看似完整实则误导的数字更值钱；
3. **另一个佐证（也容易被追问）**：对照组侧同样被抬升——全体新客座机组 4.69% → 匹配样本座机组 5.64%。匹配后**两组**都落在"电话渠道仍活跃、基础转化更高"的月份（may 占匹配样本 58.1%），**差距变大是样本构成转移的结果，不是算法把效应"放大"了**。

### 预判追问 ②："29.9% 匹配率，代表性怎么查？你说 ATT 只代表一部分人——这部分人是谁、能不能指给我看？"

**可以，而且必须能指出来**（这个问题答得越具体越加分）：

1. **看匹配样本的月份构成**（这是最直接的"代表谁"证据）：匹配成功样本中 may 占 58.1%、jul 10.1%、aug 8.9%、jun 8.4%……而原始新客里 aug/jul 的手机组分别高达 5,483/5,893 人——**被匹配进去的几乎全是"座机还在用"的月份**（may/jun 的 cellular 占比仅 31.0%/10.5%，两渠道都有充足样本）；
2. **反过来说被排除的是谁**：被剥离的 14,663 人（占手机组 70.1% = 20,922−6,259）中约 79.5% 来自 aug/jul/apr——座机渗透率 95.9%/84.8%/92.0% 的月份，座机组只有 236/1,053/149 人，**数据里根本没有这些月份的渠道对照**；
3. **所以话术要这样收口**："这份 ATT 估计的是'在两种渠道仍被真实使用的月份、能找到可比座机组的那部分新客'。对座机停用月份，本数据给不出渠道答案——但我宁愿把边界写清楚，也不假装它覆盖全员。顺带一提，方案B（精确匹配月份、专门处理月份失衡）给出 7.84pp [6.8, 8.9]，与主规格区间重叠——结论对匹配方式不敏感。"
4. **业务上怎么用**：aug/jul/apr 渠道优先级让位于名单质量（03 评分），may/jun 等月份渠道差异最大、手机渠道优先——**"哪天该用这句话"和"这句话对谁说"一起交付**，比裸报一个 +8.1pp 有用得多。

## Q4 方法局限性

**标准回答**：三句话——(1) **未观测混杂**：销售为什么给这个客户打座机而不是手机（号码可得性、现场判断、名单批次）不可观测，如果它同时影响渠道分配和转化，ATT 仍偏离真值，所以全部措辞是"经可观测因素调整后的效应估计"；(2) **共同支撑域**：ATT 只覆盖 29.9% 的新客手机组（见 Q3 预案②）；(3) **数据粒度**：无客户唯一 ID，不能做纵向追踪，生命周期分层是近似状态。

### 追问预案："回归客（returning）为什么没有 PSM 结果？你是做不出来吗？"

**做了，但被自己的质量门拦下了——这反而是设计好的行为**（00 §2.5）：

1. returning 的对照组资源严重不足：座机组仅 **403 人**（vs 手机组 5,222，13:1 失衡）；
2. 试跑 PSM 结果：匹配率 **7.7%**、匹配后 58 个特征水平中 **7 个 SMD>0.1** 失衡——按项目预设质量门（匹配率/平衡性不达标即不下结论）判定**不通过**；
3. 所以 returning 只报告朴素差异 **+2.0pp**（26.79% vs 24.81%，p=0.42 不显著）+ 显式局限声明，**不下任何效应结论**；
4. 收口话术："质量门不过就不硬做"是评估工作的底线，**质量门是评估流程的一部分，不是事后补救**——这比硬给一个看似完整的数字更可信。（业务侧配合：回归客的杠杆在历史状态——02 的 pdays_bucket0.5123/poutcome0.4939——渠道不是该层的调整对象。）

## Q5 实际工作中用得上吗（迁移回货拉拉）

**标准回答**：货拉拉质检里规则/话术调整几乎从不走 AB，只有历史观察数据——这套"没有实验条件下逼近因果"的流程可以直接迁移，我提炼了 04 里具体踩出来的五个经验（每个都挂着一个真实数字）：

| # | 经验 | 04 里的证据 |
|---|---|---|
| ① 可做性检查先于一切 | 强度型变量（打了多少电话/跟进几轮）一律先怀疑反向因果 | `campaign` 判不通过 PSM（不可观测的销售判断驱动） |
| ② 分层先于匹配 | 按策略作用对象切层再估计，不要 pooled 混合 | 渠道效应只存在于新客：V=0.1219 vs 0.0108，过滤客 5,222 vs 403 |
| ③ 共同支撑域=现实检验 | "新策略全覆盖的时段/客群没有对照样本"就如实说估计不了 | aug/jul/apr 座机渗透率 ≥84.8%，座机 149/236/1,053 人 |
| ④ 汇报双数制 | 朴素差异 X% + 调整后 Y%（适用于 Z 类客群）一起说 | 9.51 / 7.04 / 8.13 三数联动，缺一不可 |
| ⑤ 两规格互证 | 至少两种匹配规格结论一致才进决策口径 | 方案A 8.13 [7.1,9.2] vs 方案B 7.84 [6.8,8.9] |

### 追问预案："如果给你客户唯一 ID，你会怎么重做这个项目？"

**分层三步走，每一步都对应本项目现在的短板**：

1. **生命周期从"近似状态"升级为"真实纵向状态转移"**：现在 01 的分层是"用当前记录里的历史痕迹重建的近似"（无 ID 声明），有 ID 后就能追踪同一客户"首触 → 多次触达 → 办理/流失"的真实轨迹，`pdays`/`poutcome`/`previous` 从"当年活动快照"变成动态变量，生命周期分层可以直接做状态转移建模（如生存分析/离散时间风险模型描述每个阶段停留时长）；
2. **渠道从"单次处理"升级为"时变处理（time-varying treatment）"**：现在 04 的 ATT 只回答"第一次联系用手机 vs 座机"——有 ID 后真实问题是"客户第 2、3 次触达时是否切渠道"这个随时间变化的处理，需要边际结构模型（MSM）配逆概率加权（IPTW）估计处理路径的因果效应，或按渠道首触时间分组做动态队列比较；这也会顺带解决现在 campaign 只能描述、不能入模型的问题——有 ID 后 campaign 变成"同一客户真实触达历程上的强度"而非"断言不可观测"；
3. **校验口径更硬**：现在共同支撑域靠 SMD 和月份构成间接验证，有 ID 后可以直接比较"匹配对是否真的发生在同一客户的不同时期/相似客户群"，还可以把无 ID 版估计（8.13pp）当作有 ID 版的**外部复现基准**——两版对得上，方法论的说服力完全不同。

**收口**："没有 ID 不等于不能做，是'能做但边界更宽'和'能做且边界更窄'的关系；我先把无 ID 版的边界全部声明清楚，有 ID 版在上面只会更硬。"
